# Migration status

The `komga/` Git submodule pins the behavioral and schema reference baseline at Komga commit `4ef86df`. The root `webui/` directory is the maintained Web UI source imported from that baseline. Porting is organized as vertical slices so every completed stage can start, persist data, and pass HTTP-level tests.

Compatibility targets fresh Rust installations and the explicitly covered parts of this fixed baseline. The project does not promise direct migration from arbitrary historical Kotlin databases or implementation of every Flyway migration path. Existing installations must first be upgraded with Kotlin Komga to a schema explicitly documented as supported, and must be backed up before being opened by Rust.

## Compatibility rules

1. Preserve public paths, status codes, JSON field names, headers, and media types before optimizing internals.
2. Support fresh Rust databases and the explicitly covered schema at the pinned Kotlin baseline. Rust migrations must be additive and safe when supported Flyway tables already exist.
3. Do not treat arbitrary historical Kotlin database migration paths as a completion requirement. A schema is supported only when it is documented and covered by compatibility tests.
4. Keep domain policy independent from Axum and SQLx so Kotlin unit cases can be ported without HTTP or database setup.
5. Add HTTP contract tests for each controller before marking a row implemented.
6. Treat command-line arguments, `KOMGA_*` environment variables, database-backed server settings, and `oauth2.json` as the supported configuration interfaces. Spring Boot configuration-file parsing and precedence semantics are not a porting requirement.
7. Do not perform irreversible database conversions without an explicitly accepted and documented compatibility reset; `0011_page_hashing` is the current exception and requires a backup.

## Current limitations

- Scan workers analyze ZIP/CBZ, RAR/CBR, PDF, and EPUB files, hash book files for standard and KOReader matching, hash ZIP/RAR/PDF and Divina-compatible fixed-layout EPUB edge pages, discover classified duplicate pages, import EPUB metadata, generate book covers, and schedule enabled RAR-to-CBZ conversion or source-extension repair. Conversion and selective page removal support ready local RAR4/RAR5 books, including solid archives, plus safe pages in Divina-compatible fixed-layout EPUBs. Standard NAV, NCX, and guide references to removed EPUB documents are rewritten. Encrypted and multi-volume RAR archives, password-protected PDFs, DRM-protected or obfuscated EPUB resources, and reflowable, incomplete, ordinarily referenced, or structurally ambiguous fixed-layout EPUB pages remain unsupported. KEPUB conversion runs in process and does not require an external executable.
- Series/Book queries support ranked multilingual `fullTextSearch`, the complete modern condition trees, deprecated GET parameter translation, legacy Series `search_regex`, discovery feeds, modern and legacy alphabetical groups, On Deck, and Referential filter values. Unsupported modern request bodies and sort fields return `400 Bad Request`; deprecated queries retain Kotlin's lenient unknown-parameter and unknown-sort behavior. Legacy regexes use Rust regex syntax, which intentionally does not support Java look-around or backreferences.
- Unknown Kotlin tasks remain queued and are not claimed by Rust workers.
- READY ZIP, RAR4/RAR5, PDF, and Divina-compatible fixed-layout EPUB books can hash their configured first and last pages through the existing `FindBooksWithMissingPageHash` and `HashBookPages` tasks. JPEG image hashes and rendered PDF pages use Rust's versioned RGB24 representation and intentionally differ from Java ImageIO hashes; other archive and EPUB page types retain raw-byte XXH3-128 hashing. Migration `0011` clears existing PageHash rules, thumbnails, and JPEG page hashes before regeneration. PDF matches use `image/jpeg` and a zero file size in the existing administrative wire contract. A PDF hashing task parses the document once and reuses its Hayro render cache across all selected boundary pages while preserving the existing JPEG and `RGB24_XXH3_128_V1` results. The fixed Kotlin baseline hashes only ZIP pages; RAR, PDF, and fixed-layout EPUB hashing are documented Rust extensions using the same task and API contracts.
- PageHash administration exposes matches and JPEG previews for all hashable formats, while the existing `FindDuplicatePagesToDelete` and `RemoveHashedPages` task payloads remove pages from local READY ZIP/CBZ, RAR4/RAR5, PDF, and Divina-compatible fixed-layout EPUB books. Reflowable and incomplete EPUB matches remain non-removable, so `delete-all` still returns `409` without partial task submission when any such match exists. An eligible EPUB request returns `202`; the worker removes matching EPUB 3 NAV list items, EPUB 2 NCX navigation entries, and OPF guide references while promoting retained nested navigation entries in place. It rejects the task without mutation when the target remains referenced by an ordinary retained resource or another OPF ID, or when navigation uses base-URL overrides or ambiguous structures. Removal rejects stale snapshots, duplicate or out-of-range targets, and deleting every page. ZIP raw-copies all surviving entries; PDF extracts retained pages in order and validates their rendered RGB hashes and dimensions while parsing the source and output documents once each. EPUB rewrites remove validated spine and manifest entries, remove only provably exclusive images, enforce bounded non-encrypted ZIP structure, and reanalyze the complete result. ZIP, PDF, and EPUB use same-directory `.tmp`, `.bak`, and versioned `.json` journal artifacts. The journal binds old and new file metadata, page counts, and XXH3 fingerprints to the Book so database failure restores the original source and committed replacements survive interrupted cleanup. Deep scans recover determinable journal operations after task loss and retry safe legacy artifacts against the post-scan snapshot; corrupt, symlinked, non-regular, or conflicting artifacts are preserved and block that scan from changing the database. RAR removal instead streams every retained registered page and ancillary file into a validated sibling CBZ, uses the existing `.komga-convert` temporary and backup protocol, and permanently replaces the source regardless of the Library's `convertToCbz` setting. A pre-existing CBZ target is preserved and rejects the operation. RAR page removal and regular conversion are serialized per Book. Each removed page writes `DuplicatePageDeleted` to the historical-event tables in the same transaction; RAR replacement also writes `BookFileDeleted` and `BookConverted`. The changed Book is emitted through content-domain SSE. PDF page content, resources, dimensions, rotation, and order are preserved, but bookmarks, attachments, forms, page labels, and catalog-level metadata are not. The fixed Kotlin baseline removes pages only from ZIP archives; PDF, RAR, and fixed-layout EPUB removal are documented Rust extensions that retain the same public API and task contracts.
- `GET /api/v1/history` reads Kotlin and Rust historical events with administrator-only Spring pagination. Rust currently produces `DuplicatePageDeleted`, `BookFileDeleted`, `SeriesFolderDeleted`, `BookImported`, and `BookConverted`.
- Kotlin-compatible `FindBooksToConvert`, `ConvertBook`, and `RepairExtension` tasks are persistent and deduplicated. Conversion validates the complete CBZ and source snapshot before a reversible same-directory replacement, atomically updates Book/Media/history rows, restores the RAR/CBR when persistence fails, publishes content SSE, and synchronizes search. A committed conversion permanently removes the original source. All source, target, temporary, backup, and marker paths must resolve inside the Library and must not be symlinks; conflicting targets are preserved and reject the task. Extension repair intentionally leaves a `.epub` classified as ordinary ZIP unchanged.
- Administrator `DELETE /api/v1/books/{id}/file` and `DELETE /api/v1/series/{id}/file` enqueue priority-8 `DeleteBook`/`DeleteSeries` tasks and return `202` even for unknown IDs. Deletion is permanent and limited to registered source files and `SIDECAR` thumbnails. Existing paths are canonicalized before any unlink; non-local or out-of-Library paths reject the whole task, unknown directory entries are preserved, and the Library root is never removed.
- Administrator `POST /api/v1/books/import` accepts Kotlin-compatible batches and enqueues priority-8, Series-grouped `ImportBook` tasks. COPY, MOVE, HARDLINK-with-copy-fallback, destination names, one-shot upgrades, Book artwork sidecars, user thumbnails, metadata, media, progress, and read-list transfer are implemented. Sources must be non-symlink regular files outside every Library; targets are staged and database failures restore replaced or moved files on a best-effort basis. A supplied but missing or cross-Series `upgradeBookId` is rejected instead of reproducing Kotlin's inconsistent pseudo-upgrade behavior.
- Administrator `POST /api/v1/transient-books` scans only supported non-hidden regular files without following directory symlinks and rejects unreadable roots or any canonical overlap with a configured Library as `ERR_1017`. Analysis is synchronous on a blocking worker and remains process-local; cached candidates expire after one idle hour or capacity pressure. Preview pages return rendered JPEG for PDF and extracted media for archive/fixed-layout EPUB candidates.
- `/sse/v1/events` emits Kotlin-compatible names and JSON for library, series, book, collection, read-list, progress, thumbnail, and session changes. Progress and session events are user-scoped, `BookImported` is administrator-scoped, lagging subscribers skip old best-effort notifications, and search recovery remains explicit.
- OPDS 1.2 and OPDS 2 use proxy-aware absolute links and enforce library sharing, age, and sharing-label visibility before returning catalogs or reading resources. The OPDS 2 authentication document exposes Basic; OAuth remains a separate browser-login flow.
- KOReader synchronization requires a Library with `hashKoreader` enabled and a user with the `KOREADER_SYNC` role. Clients place a Komga API key in `X-Auth-User`; user creation remains disabled. Document-hash lookup applies the same library, age, and sharing-label visibility as REST before progress is returned or changed.
- Kobo synchronization requires a user with `KOBO_SYNC` and places the plaintext API key in the `/kobo/{apiKey}` path. File delivery additionally requires `FILE_DOWNLOAD`. Only visible, non-deleted READY EPUB books and the virtual `KOMGA-ONDECK` tag are snapshotted. Interrupted snapshots are retained until synchronization resumes or `DELETE /api/v1/syncpoints/me` resets them. In-process KEPUB output is temporary and cached for five idle minutes; eligible historical EPUBs missing KoboSpan positions receive a low-priority analysis task at startup. Store proxying is disabled by default, targets only `https://storeapi.kobo.com`, and forwards official authorization/device headers but never the local path key.
- `GET/PATCH /api/v1/settings` reads and atomically updates Kotlin-compatible `SERVER_SETTINGS`. Task concurrency, future remember-me sessions, remember-key rotation, cleanup policy, thumbnail size, Kobo proxy/public port, and external kepubify fallback selection update live. Main port and context-path overrides intentionally take effect after restart.
- `/actuator/info` exposes Cargo version/build time and build-script Git branch, commit ID, and commit time to administrators. Source archives without Git metadata use `unknown` and the Unix epoch. `/actuator/metrics` exposes the nine Komga application metrics rather than a general JVM/Micrometer registry. Content gauges are live SQLite snapshots; task execution and failure values are process-local and reset after restart. Announcement and release routes are administrator-only, use fixed Komga and GitHub upstreams, and cache only successful responses for one idle hour. Announcement read state is persisted per user. The font family catalog is built at startup, local families override bundled names, and symlinked or out-of-root files are rejected; font CSS and resources remain anonymous for reader compatibility.

## Next slice

The next compatibility slice should audit the remaining `Partial` SQLite and Media rows against the pinned Kotlin baseline, distinguishing real behavior gaps from intentionally unsupported historical or Spring/JVM compatibility. API route parity, supported search behavior, Series artwork sidecars, database-backed dynamic server settings, the Operations API, in-process KEPUB conversion, embedded Web UI packaging, uncommon image conversion, safe navigation-aware fixed-layout EPUB page removal, and browser core-workflow coverage now close their respective HTTP, search, scanner, configuration, administration, Kobo delivery, media, and browser-client gaps. Kotlin's `koboPort` is an advertised-port correction for direct device URLs, not a dedicated listener.

### In-process KEPUB conversion

`komga-media` exposes a synchronous reader/writer converter with cooperative cancellation. Its default behavior targets
`kepubify` v4.0.4 compatibility, including Kobo CSS and wrappers, deterministic sentence and image spans, OPF cover and
dummy-title-page updates, filtered ancillary files, and a standards-compliant EPUB ZIP layout. The compatibility corpus
compares entry sets, OPF and DOM semantics, and span identities rather than compressed ZIP bytes. Optional typography,
custom CSS, find/replace, hyphenation, old-firmware fullscreen fixes, and the complete `kepubify` CLI are out of scope.

Ordinary reflowable EPUBs advertise KEPUB without configuration. Native KEPUB and fixed-layout publications retain their
existing delivery formats. A configured `kepubify` path remains visible through the existing settings contract and is used
only as a fallback for invalid or incompatible content after archive safety and size checks pass. Cancellation, I/O,
unsafe archives, and resource-limit failures cannot invoke the fallback. Both in-process and fallback output must reopen
as a valid EPUB, contain a correct mimetype and package, and preserve source content documents before entering the cache.

Conversion is limited to 65,535 ZIP entries, 16 MiB per transformed XML/XHTML document, 256 MiB across transformed
documents, and 4 GiB of declared uncompressed data. Duplicate, absolute, backslash, traversal, symlink, encrypted, and
case-ambiguous entries are rejected. A two-permit semaphore bounds conversion work, requests for the same source snapshot
share one five-minute idle cache entry, and generated files remain process-local temporary files. Startup queues priority-0
analysis only for READY reflowable non-native EPUBs whose nonempty positions all lack KoboSpan data. The translated code
retains kepubify's MIT attribution in the workspace `NOTICE` file.

Book and series metadata can be patched through the Kotlin-compatible administrator routes. The HTTP boundary preserves
each field's distinct omitted-versus-null behavior, while `komga-core` owns normalization and validation. Bulk book
updates validate before writing, ignore missing IDs, and enqueue one deduplicated `AggregateSeriesMetadata` task per
affected series. `komga-storage` atomically replaces metadata relations and aggregations using the existing schema.

Per-book reading progress now supports one-based page updates, completion, idempotent deletion, and REST Readium
progression retrieval and synchronization. Locators are validated against analyzed media, serialized as Kotlin-compatible
gzip JSON, and series progress counts are rebuilt in the same transaction. Equal or older progression timestamps return
`409 Conflict`; book visibility restrictions are applied before progress is read or changed.

Original book files are served from both the canonical REST path and its filename-suffix compatibility alias. The
response uses the analyzed media type and current filesystem length, preserves Spring-compatible UTF-8 attachment
filenames, and streams the source in 8 KiB chunks without buffering the complete file.

Media processing remains isolated in `komga-media`: archive, PDF, EPUB, and image implementations depend on the
lightweight models and profile classification in `komga-core`. The storage layer reads and writes Kotlin's
`MediaExtensionEpub` class name and gzip-compressed JSON representation without format dependencies.

The ZIP, RAR, PDF, and EPUB paths use linked Rust dependencies and do not require `7z`, `unzip`, `unrar`, Poppler, PDFium, or `kepubify`. RAR support uses `rars` with stable default features; encrypted and multi-volume archives retain Kotlin's unsupported status and error codes. PDF support uses Hayro for analysis, rendering, and single-page extraction and requires Rust 1.96.1 or newer; password-protected PDFs remain unsupported. EPUB uses `roxmltree` and `quick-xml` for package XML and `scraper`/`html5ever`/`ego-tree` for tolerant XHTML inspection and conversion; ordinary EPUB positions follow the Readium 1024-byte rule and receive Kobo spans from the in-process converter. The image pipeline decodes JPEG, PNG, GIF, WebP, BMP, TIFF, ICO, JPEG XL, JPEG 2000 JP2/J2C, DXT1/3/5 DDS, TGA, Radiance HDR, OpenEXR, PNM, Farbfeld, and QOI for dimensions and JPEG/PNG conversion. The JPEG XL and JPEG 2000 paths are pure Rust and do not invoke external image tools. Builds with `heif-native` link to `libheif` 1.17 or newer and add HEIF/HEIC through an HEVC decoder plus AVIF through an AV1 decoder; startup reports the capabilities actually present. Detected native formats whose decoder is absent, and other unsupported image types, can still be served unchanged but cannot be converted into generated JPEG thumbnails.
